# traceable

에이전트가 **"왜 그렇게 했는지" 댈 수 있는 정도**를 재는 다섯 축.

표준 라이브러리만 씁니다. 모델도, GPU도, 설치할 의존성도 없습니다.

## 왜

요즘 에이전트 평가는 대부분 *얼마나 맞히나*를 잽니다. 그런데 다루는 지식이
늘수록 왜 그렇게 했는지 설명하기 어려워진다는 보고가 이어지고 있고,
귀속(attribution) 기반 설명은 **특정 실행이 왜 그렇게 됐는지**는 짚지 못합니다.
궤적 수준에서 잴 자가 필요합니다.

이 도구는 성능을 재지 않습니다. **추적 가능성**을 잽니다.

## 다섯 축

| 축 | 무엇을 재나 |
|---|---|
| `path` | 판단이 일어난 단위 중 그 경로가 기록으로 남은 비율 |
| `evidence` | 경로가 남은 단위 중 실제 근거가 연결된 비율 |
| `source` | 근거로 채택된 항목 중 출처가 보존된 비율 |
| `learning` | 갈림길 중 그 선택이 실제로 무언가를 바꾼 비율 |
| `origin` | 지금 상태를 기존 기록으로 설명할 수 있는 비율 |
| `replay` | 그 기록만으로 결정을 **다시 돌려 같은 값**을 얻을 수 있는 비율 |
| `continuity` | 이전 시점에 확신하던 것이 지금도 확신으로 남아 있는 비율 |

`replay`는 나머지보다 한 단계 강한 요구입니다. 기록이 남았다고 결정을
재현할 수 있는 건 아닙니다. `continuity`는 시점이 둘 이상일 때만 잴 수
있고, **"일주일 전과 같은 존재인가"**에 가장 가까운 자입니다.

**하나로 합치지 않습니다.** 어디가 끊겼는지 알아야 고칠 수 있으니까요.
분모가 0인 축은 `None`으로 나옵니다 — *0점*이 아니라 *못 쟀다*는 뜻입니다.

## 쓰는 법

```python
from traceable import Trace, score, series, table

t = Trace(
    units=[  # 판단 단위 — 트리·노드·스킬·도구 무엇이든
        {"id": "plan", "used": True, "path_logged": True, "evidence": 3,
         "branches": [{"options": {"A": 0.7, "B": 0.3}}]},
    ],
    items=[  # 근거가 된 항목
        {"id": 1, "accepted": True, "source": "https://…", "text": "…"},
    ],
    state={"바다": 3.0, "노래": 2.0},   # 지금 관심·우선순위
    step=197, size=170,
)
print(score(t))
```

여러 시점을 넣으면 **시간에 따라 유지되는지**가 보입니다.

```python
print(table(series([t1, t2, t3])))
```

## 어댑터

```python
from traceable.adapters import from_generic, from_langgraph, from_rag, from_molang
```

`from_generic`은 필드 이름만 알려주면 옮겨줍니다.
RAG처럼 판단 단위가 없는 구조는 `path`가 `None`으로 나옵니다 — 그게 정확한
결과입니다. 문서는 남지만 *어떤 경로로 판단했는지*는 없으니까요.

## 어디서 나왔나

지속 정체성 에이전트 하나를 274회차·28개 시점에 걸쳐 계측하면서 만든
자입니다. 기억이 5.5배 늘어나는 동안 `path` 0.93, `source` 1.00이
유지되었고, 27개 구간의 `continuity` 평균은 0.9975였습니다
(확신하던 1,018건 중 뒤집힌 것 0건).

## 한계

- 다섯 축과 그 임계값은 표준이 아닙니다. 제안입니다.
- 이 도구는 기록이 **남아 있는지**를 잽니다. 그 기록이 **옳은지**는 재지 않습니다.
- 축이 높다고 좋은 시스템이라는 뜻이 아닙니다. 설명할 수 있다는 뜻입니다.
